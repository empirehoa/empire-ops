# Agent Reports — Vera Automation System

## Overview

Vera runs 12 automation agents via Vercel cron at **06:00 UTC daily**. All agents are
TypeScript API routes under `/api/automation/` protected by `AUTOMATION_SECRET`.
The cron entry point is `/api/cron/run-all`, which delegates to `/api/automation/run-all`.

## Agent Status API

**Endpoint:** `GET /api/admin/agent-status`
**Auth:** Admin session (super_admin or tenant_admin)

Returns a consolidated JSON payload with:
- Status and metadata for all 12 agents
- Last report date and build status (parsed from markdown reports)
- System totals (core vs intelligence agents, legacy report count)

**Example:**
```bash
curl -H "Cookie: sb-access-token=..." \
  https://vera.empirehoa.com/api/admin/agent-status
```

## Agent Report API

**Endpoint:** `GET /api/admin/agent-reports?agent=<agent-name>`
**Auth:** Admin session (super_admin or tenant_admin)

Returns the full markdown content of a specific agent's latest report with metadata.

**Example:**
```bash
curl -H "Cookie: sb-access-token=..." \
  "https://vera.empirehoa.com/api/admin/agent-reports?agent=analytics-intelligence"
```

## Discord Notifications

Discord embeds are sent via `src/lib/services/discord-notify.ts`:

| Function | Purpose |
|---|---|
| `postAgentReport()` | Single agent report with metrics and severity |
| `postDailyDigest()` | Consolidated digest after run-all completes |
| `postStatusMessage()` | Ad-hoc status messages |

Color coding: green (healthy), yellow (warning), red (critical).

Requires `DISCORD_WEBHOOK_URL` or `DISCORD_AUTOMATION_WEBHOOK_URL` environment variable.

## Adding a New Agent

1. Create the API route at `src/app/api/automation/<agent-name>/route.ts`
   - Use `verifyAutomationSecret()` for auth
   - Use a service-role Supabase client (bypasses RLS)
   - Return JSON with results summary
2. Add the agent to the `AGENT_REGISTRY` array in `src/app/api/admin/agent-status/route.ts`
3. Add a `callAutomation('<agent-name>', secret, appUrl)` entry in `src/app/api/automation/run-all/route.ts`
4. Optionally call `postAgentReport()` from `@/lib/services/discord-notify` at the end of the handler

## Legacy Markdown Reports

The `-latest.md` files in this directory were generated by earlier Claude Code sessions.
They are retained for historical reference. The agent status API parses their headers
to extract run dates and build status. New agent runs write results to the database
and post to Discord rather than writing markdown files.

## Environment Variables

| Variable | Purpose | Required |
|---|---|---|
| `AUTOMATION_SECRET` | Auth header for all `/api/automation/*` calls | Yes |
| `CRON_SECRET` | Vercel-managed token for cron endpoint | Auto (Vercel) |
| `NEXT_PUBLIC_APP_URL` | Base URL for internal fetch calls | Yes |
| `SUPABASE_SERVICE_ROLE_KEY` | Bypasses RLS for automation writes | Yes |
| `DISCORD_WEBHOOK_URL` | Discord webhook for notifications | Optional |
| `DISCORD_AUTOMATION_WEBHOOK_URL` | Alternative Discord webhook (fallback) | Optional |

## Architecture

```
Vercel Cron (06:00 UTC)
  |
  v
/api/cron/run-all (CRON_SECRET auth)
  |
  v
/api/automation/run-all (AUTOMATION_SECRET auth)
  |
  +-- callAutomation('post-assessments', ...)
  +-- callAutomation('late-fees', ...)
  +-- callAutomation('payment-plans', ...)
  +-- callAutomation('collection-escalation', ...)
  +-- callAutomation('escalate-violations', ...)
  +-- callAutomation('generate-meeting-packets', ...)
  +-- callAutomation('generate-recurring-work-orders', ...)
  +-- callAutomation('sales-intelligence', ...)
  +-- callAutomation('financial-health', ...)
  +-- callAutomation('client-retention', ...)
  +-- callAutomation('cross-sell', ...)
  +-- callAutomation('competitive-intel', ...)
  +-- callAutomation('sync-notion-daily', ...)
  |
  v
Discord webhook (success/failure embed)
```

Admin monitoring:
```
GET /api/admin/agent-status  --> Consolidated agent dashboard JSON
GET /api/admin/agent-reports  --> Individual report content
Settings -> Automation UI    --> Per-job run/pause/schedule controls
```
